## 修复打卡成功后界面不保留Done状态

### 根因
`toggleQuickCheck` 里手动点 ✓ 打卡后，只给按钮加了 `.checked` class，但没有切换到 Done UI（没有隐藏 timer 输入框、没有显示 ✓ Done 消息）。导致打了卡但界面还显示 timer 输入框，看起来像没打卡。

### 修复
- 提取 `showDoneUI(key)` 公共函数，统一处理"隐藏 timer-set / 显示 ✓ Done"
- 在 `toggleQuickCheck`（手动打卡）、`autoCompleteTimer`（计时完成）、`renderQuickCards`（页面加载恢复）三处统一调用 `showDoneUI(key)`
- 提交：`a42d8f2`，已推送到 GitHub Pages

### 根因分析
1. **时区bug**：代码全程使用 `new Date().toISOString().slice(0,10)` 获取日期，该方法返回 UTC 时间。在中国（UTC+8）凌晨 0~8 点使用时，日期会比本地时间少一天，导致打卡日期记录错误。
2. **脏 timer state**：`renderQuickCards()` 判断是否显示 Done 状态时，如果 `ts[key].running = true`（即使 timer 已不运行），会错误跳过 Done 状态显示。

### 修复内容
- 新增 `localDateStr(date)` 辅助函数，用本地时间（`getFullYear/getMonth/getDate`）替代 UTC 时间
- 把所有 `toISOString().slice(0,10)` 替换为 `localDateStr()`（涵盖：TODAY_KEY、autoCompleteTimer、getQuickStreak、renderQuickCards、toggleQuickCheck、todayExpenses、addExpense）
- `renderQuickCards` 改为同时检查 `ts[key].running && ts[key].remainingSec > 0` 才认为 timer 真正在运行，并在已打卡但非实际运行状态时清理脏 state
- 提交：`b633ebb`，已推送到 GitHub Pages
